# 크로스링크 (CrossLink)

비스트를 기르는 **테이머**와 덱으로 싸우는 **듀얼리스트**가 한 대륙에 공존하는 2D 크로스오버 RPG.
두 진영은 **각자 자기 규칙 그대로** 싸우며, 서로 다른 규칙끼리도 대결할 수 있다.

> 몬스터 육성 RPG와 카드 듀얼 게임, 두 장르의 규칙을 구현한 오리지널 작품입니다.
> 생물·카드·세계관·그래픽은 모두 이 게임을 위해 새로 만든 것입니다.

## 실행

설치나 빌드가 필요 없습니다. `index.html`을 브라우저로 열면 됩니다.

| 조작 | 키보드 | 터치 |
|---|---|---|
| 이동 | 방향키 / WASD | 십자 패드 |
| 대화·조사·확인 | Z / Enter / Space | A |
| 메뉴·취소 | X / Esc | B |

전투는 버튼과 카드를 클릭(탭)해서 진행합니다. 진행 상황은 브라우저에 자동 저장됩니다.

타이틀의 **자유 대전**에서 네 가지 대진(비스트 vs 비스트 / 덱 vs 덱 / 비스트 vs 덱 / 덱 vs 비스트)을 바로 체험할 수 있습니다.

## 게임 내용

- **월드**: 새싹 마을 → 풀잎길 → 카드리아 시 → 속삭임 숲 → 리파 마을 → 물결 해안 → 잿빛 동굴 → 크로스 시티, 그리고 확장 지역 설빙 고개 · 서리 마을 · 고대 유적 (실내 포함 맵 32개, NPC 91명)
- **스토리**: 엠블럼 4개(테이머 도장 2 + 듀얼 홀 2)를 모아 크로스 리그에 도전. 라이벌 레온(테이머)·미라(듀얼리스트), 두 세계를 다시 갈라놓으려는 분리단.
- **비스트 46종** (10속성: 얼음 추가): 포획, 레벨업, 기술 습득, 진화, 9속성 상성, 상태이상, 특성, 날씨, 지닌 도구
- **카드 95종**: 몬스터(일반/효과/제물 소환), 마법(일반/장착/지속), 함정, 덱 편집(20~30장), 카드 팩
- 상점, 링커 센터(회복·보관함), 도감, 전설의 비스트, 엔딩 후 콘텐츠

NPC에게 승부를 걸면 **비스트로 싸울지 덱으로 싸울지** 고릅니다. 상대가 테이머든 듀얼리스트든 상관없습니다.

## 할 거리

- **스토리**: 엠블럼 4개 → 크로스 리그 → 엔딩.
- **확장 지역**: 설빙 고개(얼음 비스트), 서리 마을(도장 관장 설화), 고대 유적(엠블럼 4개로 열리는 던전과 수호자 아누, 대융합의 진실).
- **배틀 타워**: 층마다 무작위 테이머/듀얼리스트. 연승할수록 강해지고, 이길 때마다 BP를 얻어 교환소에서 희귀 도구·카드로 바꾼다.
- **의뢰 18종**: 포획·카드 수집·승리 횟수·크로스전·타워 연승·보스 격파 등. 메뉴나 크로스 시티 의뢰소에서 보상 수령.
- **재대결**: 챔피언이 된 뒤 관장·마스터·수호자가 전력으로 다시 상대한다.
- **전설의 비스트 3마리**, 도감, 카드 컬렉션, 융합 조합 찾기.

## 난이도와 성장

- 경험치는 상대 레벨이 높을수록 많이 들어온다(`X.expMult`). 약한 상대를 잡는 것으로는 잘 오르지 않는다.
- 모든 트레이너와 싸우고 야생에서 조금 단련하면 보스보다 2~3레벨 낮게 도착하도록 레벨을 맞췄다. 그 차이는 추가 단련, 속성 대비, 도구로 메워야 한다. 6레벨 이상 낮으면 초중반 보스는 사실상 이길 수 없다.
- 보스 테이머는 5~6마리 팀과 지닌 도구, 회복약을 쓰고, 보스 듀얼리스트는 LP가 10~50% 더 많다.
- 대결 전 VS 화면에 상대 레벨이 표시된다. `node tools/curve.js`로 곡선을 확인할 수 있다.

## 확장 규칙

**비스트 쪽**
- **특성** 15종: 종마다 하나. 핀치 강화(불씨/격류/신록 본능), 오기, 기선 제압, 접촉 시 상태이상(독 가시·대전 체질·달궈진 몸), 옹골참, 가속, 빛의 가호, 두꺼운 털가죽, 등장 시 날씨를 바꾸는 특성 3종.
- **날씨**: 쾌청·비·모래바람. 기술 위력과 턴 종료 피해에 영향.
- **지닌 도구** 4종: 남은 열매, 생명의 구슬, 기합의 띠, 속성 부적. 메뉴에서 비스트에게 들려 준다.
- **기술 효과**: 방어 태세, 연속기(2~5회), 반동기, 급소기, 선공기, 혼란, 풀죽음, 날씨 기술.

**카드 쪽**
- **특수 소환**: 조건을 채우면 일반 소환과 별개로 패에서 소환.
- **융합**: 「융합」으로 필드의 몬스터 2장을 합친다. 속성 조합(불+바람, 물+땅, 빛+어둠, 전기+바람, 풀+물)마다 다른 융합 몬스터가 나온다.
- **기동 효과**: 앞면 몬스터가 한 턴에 한 번 쓰는 효과(LP 지불·자신을 제물로 등 비용 포함).
- **그 외**: 토큰, 전투 내성, 직접 공격, 격파 시 강화, 날씨 마법, 마법 발동을 무효로 하는 카운터 함정.

**크로스에서의 맞물림**: 기선 제압은 몬스터 전체 ATK -200, 접촉 특성은 공격해 온 몬스터에게 상태이상, 옹골참은 「파괴」 효과도 버틴다. 날씨는 비스트의 기술과 카드 몬스터(불·물 ATK ±300, 땅 DEF +400)에 동시에 작용하므로, 한쪽이 부른 날씨를 상대가 역이용할 수 있다. 방어 태세는 다음 몬스터 공격 한 번을 막는다.

## 세 가지 전투 규칙

### 비스트 룰 (테이머 vs 테이머)
양쪽이 동시에 행동을 고르고 스피드 순으로 움직입니다. 속성 상성, 자속 보정, 급소, 능력 랭크, 독·화상·마비·수면, 교체, 도구, 포획, 도주.

### 카드 룰 (듀얼리스트 vs 듀얼리스트)
번갈아 턴을 진행합니다. 턴당 일반 소환 1회, ★5~6은 제물 1장·★7 이상은 2장, 공격/수비 표시와 뒷면 세트, 리버스 효과, 장착·지속 마법, 상대 행동에 반응하는 함정. LP 0 또는 덱 소진 시 패배.

### 크로스 룰 (테이머 vs 듀얼리스트)
핵심 원칙: **자기 쪽 자원은 자기 규칙을 따른다.** 비스트는 HP·속성·상태이상을 가진 채로, 카드 몬스터는 HP 없이 ATK/DEF 비교로 파괴되는 채로 싸웁니다.

| 상황 | 처리 |
|---|---|
| 승패 | 테이머는 비스트 전멸 시, 듀얼리스트는 LP 0(또는 덱 소진) 시 패배 |
| 턴 | 번갈아 진행. 듀얼리스트는 한 턴에 소환·마법·공격을 모두, 테이머는 행동 1회 |
| 비스트 → 몬스터 | 기술이 **스트라이크**(공격 × K × 위력/60 × 자속 1.2 × 상성)로 환산. ATK(수비 표시면 DEF) 이상이면 파괴, 공격 표시였다면 초과분이 LP 데미지. 못 부수면 **충격**으로 ATK/DEF를 스트라이크의 절반만큼 깎음 |
| 비스트 → 빈 필드 | 스트라이크가 그대로 LP 데미지 |
| 몬스터 → 비스트 | 비스트 룰의 데미지 공식으로 HP를 깎음 (몬스터 속성 vs 비스트 속성 상성 적용) |
| 스피드 | **쾌속**: 몬스터를 격파했을 때 스피드 환산치 ≥ 그 몬스터 레벨 × 400이면 1회 추가 행동 |
| 카드 효과 → 비스트 | 「파괴」는 최대 HP의 35% 피해, 효과 데미지는 선두 비스트가 대신 받음, ATK 증감은 능력 랭크 변화, 「패로 되돌린다」는 강제 교체 |
| 상태이상 | 양쪽에 공통. 몬스터는 독(매 턴 ATK/DEF −200), 화상(ATK −30%), 마비·수면(공격 불가) |
| 함정 | 비스트의 공격 기술과 교체에도 반응 |

**링크 레벨**: 카드의 수치는 절대값이고 비스트의 능력치는 레벨에 따라 커지므로, 환산 계수 K를 상대의 격(레벨)에 맞춰 정합니다 (`K = 2300 / Lv^1.43`). 그래서 비스트의 레벨업과 덱의 카드 품질이 각각 의미 있는 성장이 됩니다.

상수는 AI끼리의 대전 시뮬레이션으로 조정했습니다. 동급 대진에서 테이머 : 듀얼리스트 승률은 초반 59:41, 중반 43:57, 후반 51:49 수준입니다.

## 구조

```
index.html            진입점 (스크립트 태그만, 빌드 불필요)
css/style.css
js/core.js            네임스페이스, 결정론적 RNG, 유틸
js/data/              beasts.js(속성·기술·비스트·도구)  cards.js(카드·덱·팩)  world.js(맵·NPC·스토리)
js/engine/            beast.js(개체·성장)  battle.js(전투 엔진)  ai.js(AI)      ← DOM 의존 없음
js/ui/                sprites.js(절차적 픽셀 아트)  main.js  overworld.js  battleui.js  cine.js(컷씬·연출)  menus.js  net.js(온라인 클라이언트)
server/               server.js(온라인 서버: 정적 파일, 위치 중계, 채팅, 서버 권위 대전)
tools/                sim.js(밸런스·퍼징·결정론 검증)  checkworld.js(월드 검증)  build.js(단일 파일 빌드)
```

모든 그래픽은 코드로 그립니다. 외부 이미지·라이브러리가 없습니다 (웹 폰트만 선택적으로 불러옵니다).

**연출과 컷씬** (`js/ui/cine.js`): 그림과 자막으로 된 오프닝, 대결 전 VS 화면, 대화 초상화와 레터박스, 트레이너와 눈이 마주칠 때의 카메라 줌, 엠블럼 수여·진화 연출, 충격 섬광, 엔딩 크레딧. 필드에는 지역별 색감·빛줄기·떠다니는 입자·구름 그림자·원경 산이 깔리고, 나무와 풀이 흔들리며, 캐릭터는 24×32 픽셀·4프레임으로 걷습니다.

**2.5D 표현**: 필드는 CSS 3D 장면입니다. 지면을 기울인 원근 카메라 아래에 건물은 벽·박공 지붕을 가진 입체 상자로, 나무·바위·가구·캐릭터는 카메라를 향해 서는 판으로 세웁니다. 전투는 원근 바닥 위에서 진행되고, 카드는 필드에 눕고 몬스터가 그 위로 솟아오릅니다. 게임 로직은 타일 좌표 그대로이며 그리는 방식만 바뀝니다.

```bash
npm test
```

```bash
npm run build
```

`npm test`는 월드 데이터 검증(좌표, 워프, 도달 가능성)과 전투 시뮬레이션(승률, 무작위 행동 퍼징, 리플레이 일치)을 돌립니다. `npm run build`는 `dist/crosslink.html` 단일 파일을 만듭니다.

## 온라인 플레이

서버 컴퓨터 한 대에서 아래 명령을 실행합니다. Node.js만 있으면 되고 추가 설치는 없습니다.

```bash
node server/server.js
```

실행하면 접속 주소가 출력됩니다. 서버 컴퓨터에서는 `http://localhost:8080`, 같은 공유기에 연결된 다른 기기에서는 `http://<서버 IP>:8080`으로 접속합니다. 포트를 바꾸려면 `node server/server.js 9000`처럼 뒤에 붙입니다. 집 밖에서 접속하게 하려면 공유기에서 그 포트를 서버 컴퓨터로 포트 포워딩해야 합니다.

서버 주소로 게임을 열면 자동으로 접속됩니다.

- **월드 공유**: 같은 맵에 있는 다른 플레이어가 이름표와 함께 실시간으로 걸어 다닌다.
- **채팅**: `T` 키나 왼쪽 아래 채팅 버튼. 같은 맵이면 머리 위 말풍선으로도 뜬다.
- **대전**: 다른 플레이어 앞에서 말을 걸거나, 오른쪽 위 「온라인 N명」에서 고른다. 양쪽이 각자 비스트 팀 또는 덱을 고르므로 비스트 대 비스트, 덱 대 덱, 크로스전이 모두 된다. 팀이나 덱이 없으면 대여 편성을 쓸 수 있다.
- **대전 규칙**: 비스트는 모두 Lv.50으로 맞추고 도구 사용은 없다. 전투 결과는 내 세이브(HP, 경험치)에 영향을 주지 않는다. 전투 중 채팅과 항복이 된다.

전투는 서버가 계산합니다. 클라이언트는 행동만 보내고, 서버는 상대의 패·덱·뒷면 카드를 가린 상태만 돌려줍니다. 팀과 덱도 서버가 다시 검증해 만듭니다. 세이브는 각자의 브라우저에 저장됩니다(서버에 계정은 없습니다).

## 엔진 구조와 네트워크



전투 엔진은 처음부터 네트워크 대전을 염두에 두고 설계했습니다.

- **커맨드/이벤트 구조**: `battle.request(side)`가 그 진영이 내릴 결정을 알려 주고, `battle.submit(side, action)`이 이벤트 목록을 돌려줍니다. 사람·AI·원격 플레이어가 모두 같은 경로를 씁니다. 불법 행동은 상태를 바꾸지 않고 거부됩니다.
- **결정론**: 상태는 순수 JSON이고 난수 시드도 그 안에 있습니다. `battle.init`(초기 조건)과 `battle.log`(행동 기록)만 있으면 `Battle.replay(init, log)`로 같은 전투가 재현됩니다. `npm test`가 이를 검증합니다.
- **비공개 정보**: `Battle.viewFor(state, side)`가 상대의 패·덱·뒷면 카드를 가립니다. UI는 이미 이 뷰만으로 그려집니다.
- **동시 선택**: 비스트 룰은 양쪽 선택이 모일 때까지 기다렸다가 해결하므로 네트워크 지연에 그대로 대응합니다.
- **엔진/UI 분리**: `js/engine/`은 DOM을 쓰지 않아 Node 서버에서 그대로 돌아갑니다.

서버 권위 방식이라면 서버가 `Battle`을 돌리며 각 클라이언트에 `viewFor` 결과와 이벤트를 보내면 되고, P2P 락스텝이라면 시드와 행동만 교환하면 됩니다. `js/ui/battleui.js`의 진행 루프에서 `AI.decide` 자리에 원격 입력을 끼우는 것이 연결 지점입니다.
